# Illustrated materials evaluation

This supplements the original utility pack after parent feedback that vector-only pages did not deliver the intended actual artwork. The original 6/6 figure is a basic-usability result, not validation of generated visual quality. These four development scenarios cover recognizable subjects, picture-led stories, a labeled comparison, counted objects, and preservation through an enlargement revision. They are disclosed development cases, not an unseen holdout.

Use the existing collect/review runners with this directory as --pack and its candidate-inputs.json as --inputs. Compare the frozen vector candidate and the generated-art candidate on these exact prompts. Freeze source before collection; retain failures. Review actual PDF pages and separately report image API invocations, model identity, image reuse, latency, and qualitative visual appeal. Code tests establish embedding and exact repetition, not whether the pictures are good. Parent judgment is still needed.

The `../transfer` pack adds fresh vehicle, flower, ice-challenge and seashell subjects. Do not treat a successful
single generation as a reliability guarantee. Keep unsuccessful runs and evaluator errors visible. In particular,
no child writing does not mean no printed title or adult instruction, and repeated pointing does not require a
written record. A story's actual object states, physically possible actions and named response spaces still matter.
